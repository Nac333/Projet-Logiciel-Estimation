# AITE visual approval checklist

Use this scorecard while showing mockups. Do not confuse visual preference with tested software behavior.

| Criterion | A | B | C |
|---|---|---|---|
| Familiarity with the user's PlanSwift workflow | | | |
| Readability over an 8-hour workday | | | |
| Clear grouping of the existing ribbon tools | | | |
| Project-tree and page-selection visibility | | | |
| Drawing/PDF uses most of the central workspace | | | |
| Finish selection, quantity units and current scale visible | | | |
| Active, pending and blocked states distinguishable | | | |
| Click targets and text size usable at ordinary desktop zoom | | | |
| Preserves existing AITE operations without hidden workflow changes | | | |

Use 1-5 only as an *illustrative designer assessment*, not a validated usability measurement. Always present trade-offs, not just a winner.

## Recommended starter palette (proposal only, not existing AITE tokens)

- Workspace neutral: #EEF2F5
- Panels: #F9FBFC
- Drawing sheet: #FFFFFF
- Normal text: #263342
- Primary accent: #2468A1
- Subtle borders: #C5D0DB
- Validated: #287D55
- Review: #A96A1D
- Blocked: #B23A3A

Prioritize **relative visual hierarchy** and appropriate contrast. Avoid washed-out labels. If these tokens are used, calculate text/background contrast independently rather than asserting compliance from appearance.

## Deliverable format for each proposal

- **Version A/B/C and image:** original visual mockup, ideally 16:9.
- **What remains unchanged:** structure, tools, behaviors, calculation engine.
- **What changes visually:** 3-5 exact choices in the mockup.
- **Comfort:** font, contrast, density, screen glare, visual scanning.
- **Risk/limits:** not yet tested or not possible without code.
- **Approval decision:** waiting / approved variant ID / revision requested.

"AITE VISUEL: Propose 3 images de notre interface actuelle en gardant le ruban et les 3 panneaux comme PlanSwift. Je veux tester un bleu doux et un gris moins eblouissant. Ne touche pas au code ni a GitHub."
